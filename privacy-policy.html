2. Какие данные обрабатывает приложение

  • Данные аккаунта: адрес электронной почты и идентификатор пользователя, необходимые для регистрации, входа и синхронизации.
  • Данные прогресса: дата начала, серии дней, отметки о срывах, выполненные задания, ранг, настройки режима и другие показатели прогресса.
  • Дневник: записи, которые вы самостоятельно вводите в приложение.
  • Настроение: оценки настроения, которые вы самостоятельно сохраняете в приложении.
  • Журнал интимных записей: даты и категории записей, которые вы самостоятельно добавляете в соответствующий раздел.
  • Настройки: язык, тема, режим, косметические настройки, настройки уведомлений и другие параметры приложения.
  • Данные резервной копии: при использовании функции экспорта приложение создаёт JSON-файл с сохранённым состоянием приложения. Файл сохраняется вами самостоятельно в выбранном вами месте.

3. Где хранятся данные

Без входа в аккаунт основные данные приложения хранятся локально в браузере или на устройстве пользователя.

При использовании аккаунта состояние приложения синхронизируется с инфраструктурой Supabase. Облачная запись содержит данные состояния приложения, связанные с вашим идентификатором пользователя.

PIN-код локальной блокировки не передаётся в Supabase. Приложение хранит локально хеш PIN-кода и соль. При использовании биометрической блокировки приложение сохраняет идентификатор WebAuthn-учётных данных, а не отпечаток пальца, изображение лица или иной сырой биометрический шаблон.

4. Для чего используются данные

  • для работы функций приложения;
  • для сохранения и восстановления личного прогресса;
  • для синхронизации прогресса между устройствами при использовании аккаунта;
  • для работы настроек, дневника, статистики, календаря, журнала и других функций;
  • для аутентификации пользователя и управления аккаунтом;
  • для выполнения запроса на удаление аккаунта и связанных с ним облачных данных.

Приложение не использует пользовательские данные для рекламы и не содержит встроенной аналитической системы, такой как Google Analytics, Firebase Analytics, Sentry или PostHog, в проверенной версии проекта.

5. Сторонние сервисы

Для аутентификации и облачной синхронизации используется Supabase. Адрес проекта: gibzdydxpavidqmzivsr.supabase.co.

Для загрузки библиотек приложение также может обращаться к CDN-сервисам jsDelivr и Google Fonts. Эти обращения относятся к загрузке программных библиотек или шрифтов.

Приложение не продаёт пользовательские данные.

6. Уведомления

Если вы разрешаете уведомления, приложение использует это разрешение для показа предусмотренных приложением уведомлений и напоминаний. Настройки уведомлений сохраняются как часть состояния приложения.

7. Резервные копии

Экспорт резервной копии выполняется по инициативе пользователя. Приложение создаёт JSON-файл, содержащий состояние приложения, включая соответствующие пользовательские записи.

После экспорта копия находится под контролем пользователя. Если вы передали или сохранили такой файл в другом месте, его последующее хранение регулируется правилами соответствующего места хранения. Удаление аккаунта в приложении не может автоматически удалить отдельную копию JSON-файла, которую пользователь ранее экспортировал за пределы приложения.

8. Удаление аккаунта и данных

Пользователь с аккаунтом может инициировать удаление аккаунта из настроек приложения. При выполнении удаления приложение вызывает процедуру удаления на стороне Supabase, удаляет облачное состояние пользователя и очищает локальные данные приложения.

Также доступен внешний ресурс для удаления аккаунта:

Страница удаления: Удаление аккаунта

Пользовательские резервные копии, экспортированные в отдельные файлы, не удаляются автоматически приложением и должны быть удалены пользователем самостоятельно.

9. Срок хранения

Локальные данные хранятся до их удаления пользователем, сброса данных приложения, очистки хранилища браузера или удаления приложения в зависимости от используемой платформы.

Облачные данные аккаунта хранятся пока аккаунт используется либо до запроса на удаление. После успешного удаления аккаунта приложение удаляет связанные с ним данные из используемого облачного хранилища в рамках реализованного процесса удаления.

10. Безопасность

Передача данных аккаунта и облачной синхронизации выполняется через защищённое HTTPS-соединение. Доступ к облачным данным осуществляется через аутентифицированную сессию пользователя.

Локальная блокировка приложения предназначена для дополнительной защиты данных на устройстве и не заменяет системную блокировку устройства.

11. Права пользователя и вопросы

Вы можете использовать приложение без создания аккаунта, если соответствующая версия приложения это позволяет. Вы можете изменить или удалить локальные данные через доступные функции приложения, а данные аккаунта — посредством функции удаления аккаунта.

1. About the app

Developer: ПУТЬ

2. What data the app processes

  • Account data: email address and user identifier required for registration, sign-in, and synchronization.
  • Progress data: start date, streaks, relapse records, completed tasks, rank, mode settings, and other progress indicators.
  • Journal: entries that you voluntarily enter into the app.
  • Mood: mood ratings that you voluntarily save in the app.
  • Intimate log: dates and categories of entries that you voluntarily add to the relevant section.
  • Settings: language, theme, mode, cosmetic settings, notification settings, and other app parameters.
  • Backup data: when you use the export function, the app creates a JSON file containing the saved app state. You choose where this file is stored.

3. Where data is stored

Without an account, the main app data is stored locally in the user's browser or on the device.

When an account is used, the app state is synchronized with Supabase infrastructure. The cloud record contains app-state data associated with the user's identifier.

The local app-lock PIN is not sent to Supabase. The app stores a PIN hash and salt locally. When biometric unlocking is used, the app stores a WebAuthn credential identifier, not a fingerprint, face image, or other raw biometric template.

4. How data is used

  • to provide app functionality;
  • to save and restore personal progress;
  • to synchronize progress between devices when an account is used;
  • to provide settings, journal, statistics, calendar, log, and other features;
  • to authenticate users and manage accounts;
  • to process account deletion requests and delete associated cloud data.

The app does not use user data for advertising and the reviewed version of the project does not contain built-in analytics systems such as Google Analytics, Firebase Analytics, Sentry, or PostHog.

5. Third-party services

Supabase is used for authentication and cloud synchronization. The project uses the Supabase service at gibzdydxpavidqmzivsr.supabase.co.

The app may also access CDN services such as jsDelivr and Google Fonts to load software libraries or fonts.

The app does not sell user data.

6. Notifications

If you grant notification permission, the app uses that permission to display the notifications and reminders provided by the app. Notification settings are stored as part of the app state.

7. Backups

A backup export is initiated by the user. The app creates a JSON file containing the app state, including applicable user entries.

After export, the copy is under the user's control. If you transfer or store such a file elsewhere, its subsequent storage is governed by the rules of that storage location. Deleting an account in the app cannot automatically delete a separate JSON backup previously exported outside the app.

8. Account and data deletion

A user with an account can initiate account deletion from the app settings. During deletion, the app calls the deletion procedure on Supabase, removes the user's cloud state, and clears local app data.

An external account-deletion resource is also available:

Deletion page: Delete account

Backup files exported separately by the user are not automatically deleted by the app and must be deleted by the user.

9. Data retention

Local data is retained until the user deletes it, resets app data, clears browser storage, or removes the app, depending on the platform used.

Account cloud data is retained while the account is in use or until a deletion request is made. After successful account deletion, the app deletes the associated data from the cloud storage used by the app as part of the implemented deletion process.

10. Security

Account and cloud-synchronization data is transmitted over HTTPS. Access to cloud data is performed through an authenticated user session.

The local app lock is an additional device-level protection feature and does not replace the device's system lock.

11. User rights and contact

You may use the app without creating an account if the applicable version of the app allows it. You can change or delete local data using the available app functions, and account data can be deleted using the account-deletion function.
