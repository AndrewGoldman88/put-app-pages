2. Какие данные обрабатывает приложение

В зависимости от того, используете ли вы приложение без аккаунта или входите в аккаунт, приложение может обрабатывать следующие данные:

  • Данные аккаунта: адрес электронной почты и идентификатор пользователя, необходимые для регистрации, входа и синхронизации.
  • Данные прогресса: дата начала, серии дней, отметки о срывах, выполненные задания, ранг, настройки режима и другие показатели прогресса.
  • Дневник: записи, которые вы самостоятельно вводите в приложение.
  • Настроение: оценки настроения, которые вы самостоятельно сохраняете в приложении.
  • Журнал интимных записей: даты и категории записей, которые вы самостоятельно добавляете в соответствующий раздел.
  • Настройки: язык, тема, режим, косметические настройки, настройки уведомлений и другие параметры приложения.
  • Данные резервной копии: при использовании функции экспорта приложение создаёт JSON-файл с сохранённым состоянием приложения. Файл сохраняется вами самостоятельно в выбранном вами месте.

3. Где хранятся данные

Без входа в аккаунт основные данные приложения хранятся локально в браузере или на устройстве пользователя.

При использовании аккаунта состояние приложения синхронизируется с инфраструктурой Supabase. Облачная запись содержит данные состояния приложения, связанные с вашим идентификатором пользователя.

PIN-код локальной блокировки не передаётся в Supabase. Приложение хранит локально хеш PIN-кода и соль. При использовании биометрической блокировки приложение сохраняет идентификатор WebAuthn-учётных данных, а не отпечаток пальца, изображение лица или иной сырой биометрический шаблон.

4. Для чего используются данные

  • для работы функций приложения;
  • для сохранения и восстановления личного прогресса;
  • для синхронизации прогресса между устройствами при использовании аккаунта;
  • для работы настроек, дневника, статистики, календаря, журнала и других функций;
  • для аутентификации пользователя и управления аккаунтом;
  • для выполнения запроса на удаление аккаунта и связанных с ним облачных данных.

Приложение не использует пользовательские данные для рекламы и не содержит встроенной аналитической системы, такой как Google Analytics, Firebase Analytics, Sentry или PostHog, в проверенной версии проекта.

6. Уведомления

Если вы разрешаете уведомления, приложение использует это разрешение для показа предусмотренных приложением уведомлений и напоминаний. Настройки уведомлений сохраняются как часть состояния приложения.

7. Резервные копии

Экспорт резервной копии выполняется по инициативе пользователя. Приложение создаёт JSON-файл, содержащий состояние приложения, включая соответствующие пользовательские записи.

После экспорта копия находится под контролем пользователя. Если вы передали или сохранили такой файл в другом месте, его последующее хранение регулируется правилами соответствующего места хранения. Удаление аккаунта в приложении не может автоматически удалить отдельную копию JSON-файла, которую пользователь ранее экспортировал за пределы приложения.

8. Удаление аккаунта и данных

Пользователь с аккаунтом может инициировать удаление аккаунта из настроек приложения. При выполнении удаления приложение вызывает процедуру удаления на стороне Supabase, удаляет облачное состояние пользователя и очищает локальные данные приложения.

Также доступен внешний ресурс для удаления аккаунта, который позволяет выполнить запрос без повторной установки приложения:

URL страницы удаления: [УКАЖИТЕ ПУБЛИЧНЫЙ HTTPS-URL delete-account.html]

Пользовательские резервные копии, экспортированные в отдельные файлы, не удаляются автоматически приложением и должны быть удалены пользователем самостоятельно.

9. Срок хранения

Локальные данные хранятся до их удаления пользователем, сброса данных приложения, очистки хранилища браузера или удаления приложения в зависимости от используемой платформы.

Облачные данные аккаунта хранятся пока аккаунт используется либо до запроса на удаление. После успешного удаления аккаунта приложение удаляет связанные с ним данные из используемого облачного хранилища в рамках реализованного процесса удаления.

Отдельные технические резервные копии инфраструктурных провайдеров могут иметь собственные сроки хранения, если это предусмотрено их техническими или юридическими требованиями.

10. Безопасность

Передача данных аккаунта и облачной синхронизации выполняется через защищённое HTTPS-соединение. Доступ к облачным данным осуществляется через аутентифицированную сессию пользователя.

Локальная блокировка приложения предназначена для дополнительной защиты данных на устройстве и не заменяет системную блокировку устройства.
